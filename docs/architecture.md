# Архитектура

## Общая схема

Система построена по клиент-серверной модели и включает следующие компоненты:

- frontend-приложение
- основной backend-сервис
- file-service для работы с файлами
- PostgreSQL
- Docker Compose для оркестрации контейнеров

## Backend

Основной backend реализован на Java и Spring Boot.

Используется классическая многослойная архитектура:
- controller
- service
- repository
- entity

Backend отвечает за:
- бизнес-логику
- авторизацию и аутентификацию
- управление сущностями системы
- обработку результатов соревнований
- интеграцию с Excel
- формирование итоговых документов

## Frontend

Клиентская часть реализована на React как SPA-приложение.
Frontend взаимодействует с backend через REST API и предоставляет
интерфейсы для разных ролей пользователей.

## File Service

Отдельный сервис для:
- загрузки файлов
- хранения файлов
- удаления файлов
- выдачи ссылок на документы

## База данных

Для хранения данных используется PostgreSQL.
Управление изменениями схемы выполняется через Liquibase.

## Контейнеризация

Система запускается в нескольких контейнерах:
- db
- backend
- api
- frontend

Все контейнеры объединены через Docker Compose.
